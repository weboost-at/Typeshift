# Change the generated code

Read `docs/contributing/architecture.md` (the generator section) first. The pipeline is: discovery, parsing to
models, resolution of agents against toolsets, emitting. Each stage has rules that cost a lot when broken.

## Rules that are easy to break

- **netstandard2.0 and Roslyn 4.14.** The generator loads into older compilers. No `Index`/`Range` (`list[^1]`, list
  patterns), no APIs newer than Roslyn 4.14. The build fails with CS0518 or a missing member when you slip.
- **Equatable models.** Models hold strings, bools, `EquatableArray<T>`, `LocationInfo` and `DiagnosticInfo` only;
  never `ISymbol`, `SyntaxNode`, `Location` or `Compilation`. An agent model never holds a toolset's syntax: agents
  are resolved in a combined step (`AgentResolver`). `IncrementalTests` fail when an unrelated edit regenerates
  output.
- **Generated code calls only public library API.** It compiles into the consumer's assembly. Members only generated
  code calls are public and `[EditorBrowsable(Never)]` (D35); `InternalsVisibleTo` is not an option.
- **The selection lambda does not bind in the generator's compilation** (D29): `UseToolset<T>(tools => tools.X())`
  is read from syntax and the overload's candidate symbols. Don't try to get its `IOperation`.
- **Generated settings serialize through `StorableJson`, member by member** (D27). Source generators cannot see
  each other's output, so a `JsonSerializerContext` cannot cover generated types.
- **Output style.** `global::`-qualified names, `// <auto-generated/>` and `#nullable enable` (`SourceWriter.Header`),
  XML docs on every public generated member through `Docs` (wrapped to `SourceWriter.Width`), no member that hides an
  inherited one. Generated code compiles warning-free in a consumer with documentation on; the
  `..._Compiles_Without_Warnings` tests check it.
- **Names** come from `Emitting/Names.cs`; a member named like a neighbor gets a suffix (D2).

## Steps

1. Change the parser or model, then the emitter. Keep parsing and emitting apart: emitters read models only.
2. Run the generator tests: `dotnet test --project tests/Agentic.Generators.Tests -c Release`.
3. A changed output writes `*.received.txt` next to the snapshot in `tests/Agentic.Generators.Tests/Snapshots`. Read
   the diff; when it is what you meant, accept with `ACCEPT_SNAPSHOTS=1` and rerun. Never accept blindly.
4. Run the whole suite and both samples; the runtime tests exercise generated code end to end through a second
   assembly (`tests/Agentic.Tests.Toolsets`).
5. If the change alters what users write or see, update the guide page and the docs samples (skill `update-docs`).

## Seeing what the generator writes for a project

```shell
dotnet build samples/Agentic.Samples.Docs -c Release -p:EmitCompilerGeneratedFiles=true
ls samples/Agentic.Samples.Docs/obj/Release/net10.0/generated/Agentic.Generators/Agentic.Generators.AgentGenerator
```

For a quick experiment, add a source constant and a snapshot or `CompilesCleanly()` test in
`tests/Agentic.Generators.Tests`; `GeneratorTestBase` compiles sources with the generator, also as references
(`CompileReference`, `CompileReferenceWithoutGenerator`).
